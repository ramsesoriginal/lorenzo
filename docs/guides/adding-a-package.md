# Adding a package

Generic code (anything not specific to one app's domain logic) doesn't go in an `apps/*/utils` grab-bag. It becomes its own small package under `packages/`, with its own README and version, and tests where it has logic.

## Steps

1. Create `packages/<name>/` — a real Python package (`uv init --lib`) or npm package (`pnpm init`), whichever language fits. A TypeScript package ships its source and has no `build` ([ADR 0122](../adr/0122-api-client-package.md)).
2. Wire it to the apps that use it:
   - Python: there is no root `pyproject.toml` and no uv workspace. The package is its own uv project with its own lockfile, and each Python app that uses it declares it as a path source in its own `pyproject.toml`, for example `lorenzo-calendar = { path = "../../packages/calendar-engine" }` under `[tool.uv.sources]` in `apps/api/pyproject.toml` (see [ADR 0003](../adr/0003-polyglot-monorepo-tooling.md) for why a shared workspace was left out). If `apps/api` uses it, also add a `COPY packages/<name>` line to `apps/api/Dockerfile` and its path to the `paths:` of `.github/workflows/deploy-api.yml`, as for `calendar-engine` and `map-engine`. A tool installed from git, like `apps/cli`, takes a `git+https://...#subdirectory=` reference next to the path source.
   - JS/TS: `pnpm-workspace.yaml` already includes `packages/*`, so nothing to add there. An app or package that uses it lists it as `"workspace:*"` in its `package.json`. A Cloudflare Pages app that uses it adds its path to the app's build watch paths in its `docs/operations/<app>-setup.md`.
3. Add it to `release-please-config.json` and to `.release-please-manifest.json` (at `0.0.0`) so it gets its own version and changelog.
4. Give it a `mise.toml`. A TypeScript package copies the tasks of a recent one, for example [`packages/read-cache/mise.toml`](../../packages/read-cache/mise.toml): `lint`, `format`, `test`, `dev` (nothing to run, just an `echo`) and a hidden `install`. A Python package has `lint`, `test` and `dev`. CI treats every directory under `packages/` with a `mise.toml` as a node. Then add the directory to `[monorepo].config_roots` in the root `mise.toml`. That list is written by hand, and a package missing from it is skipped by `mise run lint`, `test` and `check` at the repo root.
5. Add it to Dependabot in `.github/dependabot.yml`: an npm package goes in the `directories` list of the one `npm` entry (see [adding-an-app.md](adding-an-app.md) for why one entry), a Python one gets its own `uv` entry. Both keep the `<eco>-minor-patch` / `<eco>-major` groups.
6. **Tell CI who depends on it** ([ADR 0148](../adr/0148-dependency-aware-pr-ci.md), `.github/ci-graph.toml`): a change to a package runs every node that uses it, computed from the dependency graph. Nodes that list it in their `package.json` (`workspace:*`) or as a uv path source are found automatically. **Anything else is declared in `.github/ci-graph.toml`: a package in a language CI can't read as `[nodes."packages/<name>"]` (the `discover` job fails until it is), a consumer it can't see as `depends_on` on that consumer's entry, and a client generated from `apps/api`'s OpenAPI schema (as `apps/cli` and the two inventory apps are) as `generated_from = ["apps/api"]` plus a `check-schema` task, so the drift check covers it.** A small package also gets `batch = "packages"` (a Python one `batch = "cli"`) so its `lint` and `test` share a runner. `python3 -m unittest discover -s .github/scripts` checks the file.
7. Create its `pkg:<name>` label (`gh label create "pkg:<name>" --color <hex> --description "packages/<name>"`), add it to the scope table in [labels-milestones-and-metadata.md](labels-milestones-and-metadata.md), and put it on the PR that adds the package.
8. List it in [`packages/README.md`](../../packages/README.md), the one list of packages; the root README, [AGENTS.md](../../AGENTS.md) and the architecture overview link there. Pre-commit hooks are optional (the older packages have a biome and tsc pair in `.pre-commit-config.yaml`); CI's `lint` is the full gate.

## When *not* to do this

If it's only ever going to be used by one app, it's not generic yet — leave it where it is until a second consumer actually shows up. Speculative reuse is how grab-bags get born in the first place.
