# Adding an app

See [ADR 0007](../adr/0007-apps-layout-and-multiplicity.md) for why this exists: `apps/` can hold any number of web frontends, mobile apps, or bots side by side — there's no fixed slot per type.

## Steps

1. **Name it by purpose, not type.** `apps/gm-console`, not `apps/web`. `apps/loot-bot`, not `apps/bot`. If you can't yet describe what makes this instance different from a hypothetical second one of the same type, that's a sign the scope isn't clear yet — confirm that before scaffolding.
2. **Confirm the language/framework and scope with the user first.** An app is added only once it has been explicitly scoped; don't scaffold code speculatively (see [AGENTS.md](../../AGENTS.md)).
3. **Give it a `mise.toml`.** This is the only contract shared tooling relies on. A static Astro app copies the tasks of the newest one, for example [`apps/maps/mise.toml`](../../apps/maps/mise.toml): `dev`, `lint`, `format`, `test`, `build`, a hidden `install`, and `test-e2e` for an end-to-end suite. Another language defines the same names in its own terms.
4. **Add it to the root `mise.toml`'s `[monorepo].config_roots`.** The list is written by hand, and an app missing from it is skipped by `mise run lint`, `test`, `dev`, `format` and `check` at the repo root.
5. **Tell CI what it depends on** ([ADR 0148](../adr/0148-dependency-aware-pr-ci.md), `.github/ci-graph.toml`). PR CI tests only what a change can affect: the changed node plus everything downstream of it, never upstream. A JS app's dependencies come from its `package.json` (`workspace:*`) and a Python app's from its `[tool.uv.sources]` path dependencies, so nothing more is needed for those. Declare the rest there:
   - **A node in any other language** (Kotlin, Swift, plain assets like `apps/brand`) is declared as `[nodes."apps/<name>"]` with `depends_on`, even an empty list. The `discover` job fails until it is.
   - `batch = "<name>"` runs a small `lint` and `test` (under a minute) on one runner with the other nodes of that name; every Astro app has one (`web-1`, `web-2`). Not with `postgres` or `shards`.
   - `depends_on` for anything CI can't derive; `generated_from` for a client generated from `apps/api`'s OpenAPI schema (which also needs a `check-schema` task so the drift check covers it); `postgres = true` if its `test` leg needs a database; `shards = N` to split a slow `test` leg over N runners (its tests read `TEST_SHARD=i/N`, as `apps/api`'s `conftest.py` does).
   - **An end-to-end suite** is a `[suites.<name>-e2e]` entry (`node`, `depends_on = ["apps/api"]`) and a hand-written job in `.github/workflows/ci.yml`: copy `e2e-maps`, change the paths, and add the job's name to `ci-summary.needs`. Lint and test need no `ci.yml` edit.
   - `python3 -m unittest discover -s .github/scripts` checks the file.
6. **Register it for releases and updates.** Add it to `release-please-config.json` and to `.release-please-manifest.json` (at `0.0.0`) so it gets independent versioning and a changelog. In `.github/dependabot.yml`, a JS app goes in the `directories` list of the one `npm` entry (the pnpm workspace shares a root `pnpm-lock.yaml`, so one entry is what makes Dependabot update the lockfile too; a member with its own entry gets a `package.json` bump and a stale lockfile). Any other ecosystem gets its own entry. Every entry has two groups, `<eco>-minor-patch` and `<eco>-major`, so weekly bumps land as two PRs and a breaking major can't hold up the routine ones — match the existing entries.
7. **A static Astro app** also needs:
   - `scripts/copy-branding.mjs` and a `build` that first runs `pnpm --filter @lorenzo/brand run build`, then `copy-branding`, which is what Cloudflare's build command relies on. Copy both from `apps/maps`.
   - A `README.md` and a `.env.example` naming `PUBLIC_API_BASE_URL`, `PUBLIC_AUTHGEAR_ENDPOINT`, `PUBLIC_AUTHGEAR_CLIENT_ID` and `PUBLIC_BRANDING_CSS_URL`.
   - Optionally the shared header and page frame, `@lorenzo/app-shell`, as Calendars, Sessions, Writing and Maps use.
8. **If it's a deployed service**, add its own deploy workflow (e.g. `deploy-<name>.yml`) — don't generalize this into a shared one across apps that might deploy completely differently (a static site vs. a container vs. a mobile app store release). **Exception**: a Cloudflare Pages static site connected via Cloudflare's own Git integration needs no GitHub Actions deploy workflow at all - Cloudflare builds and deploys directly from pushes to `main` (see [ADR 0071's addendum](../adr/0071-account-hub-stack-auth-deploy.md#addendum-2026-09-19-cloudflare-pages-git-integration-not-wrangler-action-token-upload)). Write `docs/operations/<name>-setup.md` (Pages project and watch paths, Authgear client and callback addresses, CORS, `<NAME>_URL`) from [maps-setup.md](../operations/maps-setup.md) and list it in the [operations index](../operations/README.md).
9. **If other apps link to it**, register its address in the app-links registry ([ADR 0273](../adr/0273-app-links-registry.md)): a `<name>_url` setting in `apps/api/src/lorenzo_api/config.py`, a line in `app_links.py`, a `<NAME>_URL` pass-through in `.github/workflows/deploy-api.yml`, and a mention in [deployment-setup.md](../operations/deployment-setup.md).
10. **Pre-commit hooks** are optional. The older apps have a `biome-<name>`, `astro-check-<name>` and `prettier-<name>` trio in `.pre-commit-config.yaml` (see `maps`); CI's `lint` is the full gate either way.
11. **Create its `app:<name>` label** (`gh label create "app:<name>" --color <hex> --description "apps/<name>"`), add it to the scope table in [labels-milestones-and-metadata.md](labels-milestones-and-metadata.md), and put it on the scaffolding PR and its tracking issues. Without it, the app's issues and PRs can't be filtered.
12. **List it** in [`apps/README.md`](../../apps/README.md), the one list of apps; the root README, [AGENTS.md](../../AGENTS.md) and the architecture overview describe types and link there.

## What this deliberately doesn't cover

Choosing the language/framework itself, and the app's actual domain logic — those are scoped case by case when the app is actually being built, not templated here.
