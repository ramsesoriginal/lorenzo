# Documentation

Where to look, by what you want to know.

| You want to know | Go to |
| --- | --- |
| What Lorenzo is and the world it models, in plain language | [Domain](domain/README.md) |
| How the system is put together | [Architecture](architecture/overview.md), with its [diagrams](architecture/diagrams) and [observability](architecture/observability.md) |
| Why something is the way it is | [ADRs](adr/README.md): one decision each, numbered in order |
| What is proposed or still undecided | [RFCs](rfcs/README.md) |
| How to do a task: set up, add an app or package, write a commit message, use Calendars or Sessions, read a file format | [Guides](guides/README.md) |
| How to run and host it: deploys, hosting each app, releases, going public | [Operations](operations/README.md) |
| The API, its configuration and the well-known stat names | [Reference](reference/README.md) |
| How Lorenzo looks and sounds: logo, colour, type, voice, the words the product uses | [Brand](brand/README.md) and [identity](brand/identity.md) |
| What a screen was designed to be | [Design briefs](design): [Beings](design/beings/README.md) and [Bench](design/bench/README.md), each with a prototype and screens |
| What the finished product is meant to do | [v1.0](../v1.0.md) |
| Which apps and packages exist | [Apps](../apps/README.md) and [Packages](../packages/README.md) |

The order of the process is RFC, then ADR, then issue and milestone: an RFC proposes, an ADR records the decision, and GitHub tracks the work. [ADR 0070](adr/0070-planning-milestones-issues-and-a-deferred-roadmap.md) describes it.
