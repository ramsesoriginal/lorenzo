# 0494 - Writing moves into the web shell

Status: proposed, 2026-11-18; W0 to W4 and W3a are built (the pull requests are in the tracking issue #1297), W5 to W8, the undo operation and the helpers B3 and B4 are not. The six questions are answered (below) and the plan stands on those answers; the editing habits of [WR12](../design/web/writing/README.md#wr12-three-habits-proposed) are written into it, and are proposed. Slice UI-E of [RFC 0050](../rfcs/0050-the-web-interface.md) for Writing. The design is [docs/design/web/writing](../design/web/writing/README.md) (WR1 to WR10, and [WR11](../design/web/writing/README.md#wr11-what-the-built-features-changed-proposed), which says where the built features differ from the drawing) and the decision is [ADR 0419](0419-writing-redesign.md); this ADR says how the app is moved to it, in what order, and what has to be decided first. Follows [ADR 0440](0440-calendars-moves-into-the-web-shell.md), [ADR 0441](0441-sessions-moves-into-the-web-shell.md) and [ADR 0465](0465-maps-moves-into-the-web-shell.md), which did the same for Calendars, Sessions and Maps. Nothing here is built, and the numbers of the stack's pull requests are not yet known.

## Context

Writing is feature-complete in the old interface: every slice of [RFC 0047](../rfcs/0047-lorenzo-writing.md) is built and tested end to end against the real API (2,600 lines of Playwright over about thirty scenarios). What it does not have is any of the interface that was designed: it draws its own header, its Home is a form and a list, a piece of writing is one plain text area with a column of closed panels under it, and structure is Up and Down buttons and a panel each for Move, Join, Extract and Split. The app is one page (`/`) driven by `?tenant=`, `?entry=`, `?view=outline|read` and `?review=`, written as imperative TypeScript (about 5,200 lines in `apps/writing/src/lib`), with no app-specific CSS.

Two things make this move different from Maps. The editor is the shared `@lorenzo/lorenzoscript-editor`, a `<textarea>` with a toolbar and a Preview tab, not a rich-text surface, and a page is an ordered list of text blocks, pictures and child Chapters, so the drawing's block surface has to be built around many editors, not out of one. And what is built does not support every gesture that was drawn: there is no operation that moves a block into another Chapter, and none that undoes a split, an extraction or a join (WR11, rows 3 and 6).

## Decision

- **The frame is the web shell** (`AppPage shell="web"`), as in the other apps. The page uses the `workspace` template for a work and `list-detail` for the shelf. The palette, the apps sheet and the status bar are the shell's, and the status bar holds the save state, the word count and the length goal (D18). Writing is in Build (D31).
- **A stack of twelve pull requests, each on the one before and each tested and green** (W0 to W8, with W3a being three), with the API pull requests and the small editor helpers below as their own pull requests where they are needed. A PR draws only what the API already gives; where an API read is missing, the screen shows what it can and says so, and the PR that adds the read lights it up.
- **The behaviour does not change.** Autosave, conflict handling, recovery, review grants, the structural operations and their checks, counts, goals and exports are as built. Each PR moves the existing end-to-end scenarios onto the new interface, as Maps did, and does not delete one.
- **Old addresses keep working.** `?entry=` and `?view=` redirect to the new addresses. `?review=` is never changed: those links have been given to reviewers.
- **The editor stays a source editor, on a text area, with no editor engine** (decided 2026-11-18), and the Live layout is a second package, `@lorenzo/lorenzoscript-semilive-editor` (W3a). A block surface is built around it: each text block has its own editor and a grip; pictures and child Chapters have a grip and a row. Enter and Backspace belong to the text area. Splitting a block is only the explicit, checked action of ADR 0346 and 0347.
- **App-specific CSS is allowed** where the shell's parts do not reach, as in Maps, in one file, with brand tokens only and the existing guard test.
- **Decided, 2026-11-18:** a block moves within its page only, and between Chapters by extraction (Q1: no new operation). Split, extraction and join get an undo (Q2: an operation is built, before W5). The shelf learns what has been shared with the person (Q3: a read is built, before W1 draws it). The shelf needs nothing more from the entry list yet (Q4). The addresses are `/write/`, `/read/` and `/review/` with `/` as the shelf (Q5). The updates dialog has "Select all clean" (Q6).

### The API pull requests

Each is its own ADR and its own pull request, made before the one that draws it.

- **Q2, undo (to build, before W5).** An operation that restores the writing and the outline from the structural checkpoint a split, an extraction or a join leaves, so that each can be undone as a whole. It checks that nothing changed since (the versions), refuses if it did, and says why; the retry rule of ADR 0344 applies.
- **Q3, what is shared with me (to build, before W1).** A read of the Editions that have been shared with the caller for review, so that the shelf can list them.
- **Q1, move blocks (not built).** Blocks move within their page; between Chapters they are extracted and the new Chapter moved.
- **Q4, the shelf's list (not yet).** The entry list is not changed. If it proves too poor for the shelf, this is asked again.

## Questions and the answers (2026-11-18)

1. **Q1, move blocks between Chapters?** Keep as it is: blocks stay in their page, and are moved by extraction.
2. **Q2, an undo for split, extract and join?** Yes. It is built (above) and W5 draws it.
3. **Q3, a read of what is shared with me?** Yes, for the shelf.
4. **Q4, a last-edited time and a count for the shelf?** Not yet. Continue is the last work opened in this browser.
5. **Addresses?** Yes: `/write/`, `/read/` and `/review/`, each with `?tenant=` and `?entry=`, and `/` as the shelf.
6. **Updates?** Yes: "Select all clean" ticks the clean changes and never applies.

## Consequences

- The end-to-end scenarios of `apps/writing/tests/e2e/writing.spec.ts` drive the old controls by role and label and are moved as each part moves, as in Maps. The accessibility checks leave the shell's status bar out.
- The editor package gains the two additive exports of W3a and, after W3, the small helpers of WR12 (paste from Word, find and replace, `[[` completion and quiet highlighting, B1 to B4) as opt-in options, so that every app that uses it, and the semilive editor, can have them; the block surface is the app's. If a block needs something the editor does not give (a way to know its caret is at a safe boundary), it comes from the split-points read the API already has.
- The old interface is gone from the first PR in which its part is replaced, so the old panels are removed with their replacements and not kept beside them.
- The editing habits of [WR12](../design/web/writing/README.md#wr12-three-habits-proposed) touch the stack as the design says: the wording and layout items (its A rows) are written into the PRs above, the small editor helpers (paste from Word, find and replace, `[[` completion), in the editor package, are one small PR each after W3, and the Live layout is W3a, in the stack. Decided 2026-11-18: Start writing opens a Scene at once (A1); comments on a passage for Authors (C2), search across all writing (C4) and a second pane (C5) are wanted and are each a stack of their own, with their own ADRs, after this one; Word and Markdown import and export (C3) is not yet. No code-editor engine (C1): the Live layout is paragraphs formatted with the clicked one as source, in our own code.
- The tracking issue is [#1297](https://github.com/ramsesoriginal/lorenzo/issues/1297), in the milestone of RFC 0050, made when the work was started.
