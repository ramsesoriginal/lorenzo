# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Each app under `apps/` is versioned and changelogged independently by release-please once it has a release — see [docs/operations/releasing.md](docs/operations/releasing.md). This root file is a hand-curated, high-level narrative across the whole monorepo.

## [Unreleased]

### Added

- Repository foundation: monorepo layout, tooling (mise, pnpm workspace, pre-commit, release-please), CI/CD workflows, GitHub templates and ruleset, and ADRs recording the key decisions. See [ADR 0007](docs/adr/0007-apps-layout-and-multiplicity.md) for how apps get added.
- `apps/api`: FastAPI backend infrastructure — health/readiness/metrics, async SQLAlchemy + Alembic wired to a real Postgres (`infra/docker-compose.yml`), mypy, RFC 9457 problem+json error responses, pagination, OpenTelemetry tracing (console exporter).
- `apps/api`'s full domain model (entity/component core plus tenant/user/membership, campaign/player, character/ownership, campaign GM/orga, knowledge/visibility — [ADR 0012](docs/adr/0012-entity-table.md) onward) and a full read/write REST API over it ([RFC 0001](docs/rfcs/0001-core-domain-data-model.md)/[RFC 0002](docs/rfcs/0002-campaign-player-character-model.md) and onward, landed as ADR 0020 and ADR 0030-0067) are built and merged to `main` — see [docs/architecture/overview.md](docs/architecture/overview.md#roadmap) for the detailed history.
- ADR 0008: taskiq + fastapi-limiter chosen but deferred until Redis is actually needed — still deferred. ADRs 0009/0010: Authgear as the identity provider, and the User/Tenant/Membership model — both built; real OIDC bearer-token verification is required on every tenant-scoped route ([ADR 0023](docs/adr/0023-authgear-token-verification.md)/[ADR 0027](docs/adr/0027-authgear-cloud-not-self-hosted.md)).
- ADR 0011 + CI/CD: `apps/api` now deploys continuously to Google Cloud Run + Neon Postgres on every push to `main` that touches it (`.github/workflows/deploy-api.yml`), with OIDC auth (no stored cloud credentials) and automated migrations. Confirmed live end to end.
- `apps/loot-bot`: a Discord bot built on top of `apps/api`'s write API — account linking, self-service inventory viewing/managing, loot-splitting, GM loot drops with claims, and item awarding ([ADR 0050](docs/adr/0050-loot-bot-stack-linking-and-isolation.md)/[0051](docs/adr/0051-loot-bot-give-command.md)/[0052](docs/adr/0052-loot-bot-loot-drop-and-claims.md)), deployed on Google Cloud Run over Discord's HTTP Interactions Endpoint ([ADR 0053](docs/adr/0053-loot-bot-http-interactions-and-cloud-run-deploy.md)).
- `apps/inventory-web` and `apps/account-hub`, static Astro frontends on the API ([ADR 0004](docs/adr/0004-static-astro-frontend.md), [ADR 0071](docs/adr/0071-account-hub-stack-auth-deploy.md)), deployed to Cloudflare Pages: a GM's item catalog and container board, and a user's own account, notifications, roster and administration. `apps/brand` and `packages/brand` carry their shared tokens, fonts, components and icon atlas ([ADR 0098](docs/adr/0098-branding-css-app-and-package.md), [ADR 0274](docs/adr/0274-the-atlas-grows-for-bench-kinds-and-states.md)).
- Repositories ([RFC 0024](docs/rfcs/0024-repositories.md)) and `apps/cli`, the `lorenzo` command line: tenants other tenants copy from and take updates from; creating and seeding a repository, importing MPMB standard items, publishing and offering it ([RFC 0025](docs/rfcs/0025-lorenzo-cli-mpmb-item-importer.md)). `packages/lorenzoscript` and its editor, `packages/api-client`, `packages/converters`, `packages/inventory-names` and `packages/stat-values` are the shared code under it.
- Repository tooling ([RFC 0036](docs/rfcs/0036-repository-tooling.md) to [RFC 0041](docs/rfcs/0041-entity-kinds-and-author-freedom.md)): releases and public snapshots, public repositories and Discover, the Author role, and `apps/bench`, the repository authoring workbench ([RFC 0042](docs/rfcs/0042-bench-workbench-interface.md)).
- `apps/beings`, "Lorenzo Beings": characters and NPCs drawn as a sheet that is read, played or edited, with notes in four audiences ([ADR 0270](docs/adr/0270-beings-app.md), [RFC 0043](docs/rfcs/0043-the-being-sheet.md)).
- `apps/inventory-mobile` (Android, Kotlin/Compose) and `apps/inventory-ios` (SwiftUI): inventories, encrypted offline snapshots and private notes ([ADR 0291](docs/adr/0291-inventory-mobile-native-android-app.md), [ADR 0307](docs/adr/0307-inventory-ios-and-altstore-testing.md)).
- Facts, explicit audiences and information bundles ([RFC 0044](docs/rfcs/0044-facts-audiences-and-information-bundles.md)); personal access tokens for scripts and devices ([ADR 0268](docs/adr/0268-personal-access-tokens-api.md)).
- `apps/calendars`, "Lorenzo Calendars", and `packages/calendar-engine`: authored calendars with computed years, periods, observances, Events with explicit order and causes, and a donjon import through the CLI ([ADR 0308](docs/adr/0308-authored-calendars-and-calculation.md) to [ADR 0316](docs/adr/0316-collaborative-events-facts-and-participant-audiences.md)).
- `apps/sessions`, "Lorenzo Sessions": campaign Sessions, reusable Scenes, rosters, notes, recorded play and personal lived order ([RFC 0046](docs/rfcs/0046-sessions-scenes-and-lived-order.md), [ADR 0317](docs/adr/0317-sessions-scenes-and-collaborative-planning.md) to [ADR 0319](docs/adr/0319-personal-lived-order-as-event-evidence.md)).
